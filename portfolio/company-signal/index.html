개요

회사를 알아볼 때 쓰던 인원 흐름 조회 서비스가 사라져, 공개 원천 데이터로 직접 구성

원천의 상태

방향
사업장을 평가하거나 순위를 매기지 않고, 숫자와 그 숫자의 한계(퇴사 집계 시차, 소득 상한, 소규모 사업장)를 함께 제공
데이터
국민연금 가입 사업장 자료 11년치(2015-11 ~ 2026-09), 금융위원회 기업 개황
결과물
이름으로 사업장을 찾아 월별·연도별 인원, 입사, 퇴사 지표를 보는 명령줄 도구

수집부터 조회까지

수집과 갱신

구조
받기만 여러 스레드, 파일과 DB 쓰기는 한 스레드. 저장 구조와 이어 받기는 그대로 유지
고친 문제
처음 코드는 실패한 요청과 같이 끝난 페이지를 저장하지 않고 멈춤. 이어 받기 테스트에서 발견해, 도착한 페이지를 모두 저장한 뒤 멈추게 수정
공시 수집
하루 10,000회 한도가 있어 병렬로 하지 않음
갱신 명령
명령 하나로 수집, 빌드, 공시 수집, 공시 모델 빌드 순서로 실행. 공시 대상 이름을 빌드 결과에서 가져오므로 빌드를 공시 수집 앞뒤로 두 번 둠
실패 처리
한 단계가 실패하면 뒤 단계는 실행하지 않음. 모든 단계가 이어 받기를 하므로 같은 명령을 다시 실행

사업장 키 만들기

원천에 사업장 키가 없어 번호 6자리, 정규화한 이름, 가입일로 키를 만들고 주소는 뺌

번호
사업자번호는 앞 6자리만 공개, 다른 회사끼리도 자주 겹침
주소를 뺀 이유
매달 2,400곳 정도가 이사. 주소가 키에 있으면 이사할 때마다 폐업과 신규로 보여 이력이 끊김

이름을 바꾼 사업장 잇기

이름 뒤에 영문명을 붙이자 이력이 둘로 나뉨. 그림은 예시 이름

버린 방법
괄호를 빼고 키 만들기, 번호와 가입일만 보고 잇기. 둘 다 실제 데이터에서 다른 사업장을 합침
최종 조건
번호 6자리, 가입일, 사업장 종류가 같고, 한쪽이 끝난 바로 다음 달에 다른 쪽이 시작하고, 영문명과 법인 형태 표기를 뺀 이름이 같고, 양쪽 후보가 하나씩일 때만 연결
확인
무작위 25쌍 직접 확인, 모두 같은 회사. 전체 1,057곳 연결
하지 않은 것
이름을 완전히 바꾼 경우는 다른 회사와 가를 방법이 없어 연결하지 않음

새 발행분 검사

검사
기준월마다 사업장 수와 가입자 합계를 내고, 직전 달보다 5% 넘게 변하면 경고
첫 경고
지난 자료에서 걸린 달은 2025년 6월 하나. 확인해 보니 그때부터 개인사업장 일부가 추가로 수록
수준
급변은 빌드를 멈추지 않는 경고, 키나 입사·퇴사 수가 비는 경우만 실패

원본 저장 방식 바꾸기

두 경로로 전체를 읽어 비교하니 결과가 같고 파일 쪽이 더 빨라, gzip 파일을 유일한 원본으로 결정

삭제 순서
페이지마다 파일 해시와 레코드 수가 기록과 같은지 확인한 뒤, 나머지 표만 새 파일로 옮기고 행 수를 비교. 예전 DB는 남겨 두고 다시 빌드한 결과가 같은 것을 확인한 뒤 삭제
결과
수집 DB 31GB에서 32MB

빌드가 느려진 원인

원본을 파일에서 읽게 바꾼 뒤 전체 빌드가 7분에서 29분으로 늘어남

원인
DuckDB가 파일의 행 수를 몰라, 큰 레코드 쪽을 통째로 메모리에 올리는 방식으로 실행
해결
다 받은 발행분 목록을 쿼리에 고정 목록으로 넣어 맞춰 보는 단계를 없앰, 7분대로 복구
