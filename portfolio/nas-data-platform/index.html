Problem

폴더만으로는
답할 수 없던 질문

데이터가 폴더 단위로만 관리되어, 다음 담당자는 어떤 데이터를 믿고 써야 하는지 알 수 없었습니다. 이 세 가지 질문에 답할 수 있는 구조를 목표로 잡았습니다.

원본과 전처리 버전 중 무엇을 써야 하는가?
이 결과는 어떤 입력으로 만들어졌는가?
지금 작업은 어디까지 끝났는가?
Design Decision

믿을 수 있는 것만
등록하고 연결한다

카탈로그가 틀린 정보를 보여주면 폴더보다 못합니다. 그래서 확인된 사실만 기록하고, 확인되지 않은 것은 그렇다고 표시하는 쪽을 택했습니다.

등록

파일 도착과 등록 완료는 별개

완료 기록, 파일 목록, 체크섬을 검증한 뒤에만 등록합니다. 누락, 변조, 경로 충돌이 있으면 자료를 그대로 보존하고 멈춥니다.

관리 단위

같은 촬영의 원본과 전처리를 구분

원본과 전처리 버전을 한 단위 안에서 따로 관리하고, 원본, 특정 버전, 전체 중 쓸 범위를 고를 수 있게 했습니다.

출처 추적

확인되지 않은 관계는 확정하지 않음

결과에는 실제로 사용한 입력 경로와 처리 근거를 남깁니다. 확인된 입력과 후보 관계를 구분하고, 출처를 모르는 결과에 계보를 지어내지 않습니다. 결과를 쓰는 담당자는 어떤 원본과 버전으로 만든 결과인지 바로 조회할 수 있습니다.

Failure & Recovery

중간에 끊겨도
이어서 처리한다

원본 수신, 재구성, 결과 등록, 로컬 정리로 이어지는 처리는 어느 단계에서든 끊길 수 있습니다. 단계마다 상태를 남겨, 이미 끝난 일은 다시 하지 않고 남은 일만 재시도합니다.

  • 입력: 체크섬 목록으로 다운로드를 검증한 원본으로만 시작
  • 실행: worker 프로세스가 살아 있는지와 실행 준비가 됐는지를 구분. 자원 부족은 대기, 일시적인 연결 오류는 횟수를 제한해 재시도
  • 복구: 같은 작업 ID, 계획 해시, 저널로 이어서 진행. 이미 등록된 결과는 새로 만들지 않고 정리 단계만 재시도
journal.py (요약) 
def atomic_json(path, value):
    """Write through a temporary file, fsync it,
    then replace the journal in one step."""
    path = Path(path)
    fd, temporary = tempfile.mkstemp(dir=path.parent)
    try:
        with os.fdopen(fd, 'w', encoding='utf-8') as stream:
            json.dump(value, stream, ensure_ascii=False, indent=2)
            stream.write('\n')
            stream.flush()
            os.fsync(stream.fileno())
        replace_file(temporary, path)  # atomic replace, durable rename
    finally:
        if os.path.exists(temporary):
            os.unlink(temporary)
Operation & Handoff

만든 뒤에도 쓰이도록
운영하고 넘겼다

플랫폼은 쓰는 사람이 계속 믿을 수 있어야 의미가 있습니다. 운영하면서 상태를 확인하고, 새 데이터 형식을 받아들이고, 다음 담당자가 이어받을 수 있게 정리했습니다.

운영

상태와 정합성을 계속 확인

API와 worker 상태, 실패와 보류 원인을 확인합니다. 실제 파일, 요약 JSON, 카탈로그 기록이 서로 맞는지 관리하고, 대용량 NAS 검사와 운영 모니터링을 개선했습니다.

확장

새 센서 데이터 형식 지원

새로 들어온 센서 데이터 형식도 검증한 뒤 자동으로 분류되도록 지원 범위를 넓혔습니다.

인계

다음 사람이 이어받을 수 있게

업로드와 운영 문서, 실행 예제를 제공하고, 오퍼레이터의 입력, 산출물, 완료 기준을 정리했습니다. 경로 전환 확인과 이전 자료 정리 절차를 인계했습니다.
