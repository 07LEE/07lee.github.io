NAS Data Platform

현장 수집 데이터와 처리 결과의 출처와 상태를 추적하는 카탈로그와 입고 파이프라인

Python, FastAPI, SQLite

역할
회사 업무, 설계부터 구현, 운영까지 혼자
기간
2026.09 ~ 2026.11
결과
데이터셋 178건, 약 1.85TB를 검증 후 등록
시작한 이유 전체 구성 계층과 계보 원천과 색인 중단 복구 결과

시작한 이유

폴더에 쌓인 기존 데이터를 새 계층 구조로 옮기는 마이그레이션을 맡았는데, 열어 보니 데이터 사이의 연결이 끊겨 있음

  • 어떤 원본으로 만들었는지 기록이 없는 재구성 결과
  • 다른 폴더에 흩어져 어느 촬영의 것인지 알 수 없는 전처리 버전
  • 원본이 빠지고 결과만 남은 경우
그대로 옮기면
자리는 정리되지만, 무엇이 무엇에서 나왔는지는 여전히 알 수 없음
목표
파일만이 아니라 데이터 사이의 연결까지 옮기기

전체 구성

등록
파일이 올라오면 카탈로그가 주기적으로 확인하고, 체크섬까지 맞은 것만 계층에 등록
처리
처리 워커는 새 입력을 받아 3D로 만들고, 어떤 입력을 썼는지 기록해 결과를 다시 올림
완료
카탈로그가 결과 등록을 확인해야 완료로 처리
파일 경로
데이터 파일은 API 서버를 거치지 않고 NAS로 직접 올리고 내려받음. API로는 메타데이터와 작업 상태만 주고받음
재시도
완료 기록과 체크섬 목록을 파일로 남겨, 한쪽이 멈춰도 다른 쪽이 보고 재시도

계층과 계보

결과마다 실제로 쓴 입력을 계보로 기록

계층
회사의 메달리온 구조(Bronze ~ Diamond)를 따르고, 그 안의 단위와 계보 설계를 담당
단위
같은 촬영의 원본과 전처리 버전은 한 단위로 보관, 쓰는 사람이 원본이나 특정 버전을 선택
지어내지 않음
원본을 바로 쓴 결과에 중간 단계를 거친 것처럼 계보를 만들지 않음
후보
확인되지 않은 관계는 확정하지 않고 후보로만 남겨, 확인된 계보와 섞이지 않게 함
확정 기준
데이터셋은 등록하되, 계보는 입력이 하나로 확인될 때만 확정

원천과 색인

데이터 옆 요약 파일(JSON)이 메타데이터의 원천이고, 카탈로그 DB는 빠르게 찾기 위한 색인

요약 파일
이름, 유형, 현장, 파일 수, 용량, 계층별 정보, 실제로 사용한 입력. DB 없이 저장소만 봐도 데이터가 무엇인지 알 수 있음
작업 상태
별도 작업 DB가 관리
수집
새 항목만 추가, 기존 값은 덮어쓰지 않고 차이를 보고
검증
실제 파일, 요약, DB 기록을 비교해 차이를 보고만 하고 자동으로 고치지 않음
검토 후 갱신
사람이 확인한 변경만 요약 파일과 DB에 함께 반영, 이전 값 보존
효과
DB를 잃어도 요약 파일로 색인을 다시 만들 수 있고, 어긋남은 덮어쓰기 전에 드러남. 잘못된 값은 DB 제약이 한 번 더 막음

중단 복구

계층 등록은 NAS에서 파일을 옮기고 DB에 기록하는 두 단계인데, 둘을 한 번에 확정할 트랜잭션이 없어 중간에 끊기면 파일만 옮겨진 상태가 생길 수 있음

계획 고정
무엇을 어디로 옮길지 계획을 내용 해시로 고정하고, 실행 전에 할 일을 저널에 먼저 기록
이어서 실행
저널과 대상이 맞으면 끝난 단계는 건너뛰고 남은 단계만 실행. 응답이 끊긴 이동은 대상을 다시 검사해 판단
멈춤
파일이 바뀌었거나 대상에 이미 자료가 있으면 덮어쓰지 않고 보존한 채 멈춤
정리만 재시도
등록은 끝났는데 정리만 남은 경우에는 정리 단계만 재시도
저널
임시 파일에 쓰고 디스크에 내린 뒤 한 번에 교체해, 쓰다 만 저널이 남지 않음
작업 큐
워커가 죽어도 작업을 회수해 다시 실행

결과

구분 2026년 10월 말 운영 DB 기준
데이터 신뢰성 재구성 결과 17건 중 14건은 실제로 쓴 입력 확인, 3건은 확정 전으로 구분
데이터 정합성 검증을 거친 데이터셋 178건, 파일 23.7만 개, 약 1.85TB 등록
운영 안정성 실제 환경에서 한 건을 끝까지 처리, 등록 대기와 정리 대기 0건. 운영 상태를 복원한 뒤 작업 재개 확인
운영과 인계
API와 워커 상태, 실패와 보류 원인 확인 절차와 업로드·운영 문서, 실행 예제를 정리해 인계
범위 밖
재구성 연산 자체는 외부 도구가 수행. 직접 구현한 부분은 데이터 관리, 실행 자동화, 검증, 운영 연계
